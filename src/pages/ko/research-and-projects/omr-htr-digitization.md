## 개요

손글씨 시험지를 디지털로 옮기는 일은 사실 두 가지 문제입니다. 학번과 생년월일은 칸에 마킹하는 방식이라 정밀한 **광학 마크 인식**(OMR)이 필요합니다. 서술형 답안은 원고지에 손으로 쓰기 때문에 **필기 인식**(HTR)이 필요합니다. 게다가 학생 기록이라서 어떤 데이터도 학교 밖으로 나가면 안 됩니다.

**ExamOCR**는 이 둘을 하나의 오프라인 파이프라인에서 처리합니다. 빠른 원근 보정, 투영을 이용한 격자 자르기, 필기 인식용 비전-언어 모델(Qwen2.5-VL-7B-Instruct)을 채점자용 Streamlit 앱 안에 묶었습니다.

## 파이프라인

<ol class="flow">
  <li><strong>입력</strong>스캔한 시험지 PDF나 이미지를 넣습니다.</li>
  <li><strong>정렬</strong><code>ExamAligner</code>가 네 모서리 마커를 찾아 페이지를 2828 × 2000 크기의 고정 캔버스로 펴 줍니다.</li>
  <li><strong>자르기</strong><code>ExamCropper</code>가 학번, 생년월일, 이름, 원고지 영역을 고정 비율로 잘라 냅니다.</li>
  <li><strong>마킹 판독</strong><code>read_omr_smart</code>가 픽셀 투영으로 학번과 생년월일 마킹을 읽습니다.</li>
  <li><strong>필기 인식</strong><code>transcribe_qwen</code>이 Qwen2.5-VL로 원고지 답안을 읽고, 한글 음절 필터가 결과를 정리합니다.</li>
  <li><strong>매칭·내보내기</strong>SQLite에서 학생 정보와 결과를 맞춘 뒤 채점 앱에 보여 주고 CSV로 내보냅니다.</li>
</ol>

코드는 몇 개의 모듈로 나뉩니다.

1. **화면:** 다국어 채점, 화면 위 주석, CSV 내보내기를 지원하는 Streamlit 대시보드
2. **저장:** 학생 정보, 점수, 주석 상태, 인식 결과를 담는 SQLite(`database.py`)
3. **정렬·자르기:** `utils/alignment.py`, `utils/cropping.py`
4. **마킹 판독:** 투영 기반 칸 검출(`utils/detection.py`)
5. **필기 인식:** GPU로 가속한 Qwen2.5-VL 생성(`utils/recognition.py`)

## 윤곽선 찾기를 포기한 이유

첫 프로토타입은 모든 입력 칸과 체크 박스를 윤곽선으로 찾으려 했습니다. 깨끗한 테스트 스캔에서는 잘 됐지만 실제 시험지에서는 무너졌습니다. 연필 자국, 선을 넘어간 글씨, 접힌 자국 때문에 윤곽선이 계속 깨졌고 정렬이 어긋났습니다.

그래서 더 단순하고 **결정적인**(deterministic) 방식으로 다시 만들었습니다. 먼저 페이지 전체를 반듯하게 펴고, 그다음 정해진 위치에서 영역을 잘라 내는 방식입니다.

### 1. 모서리 마커와 원근 보정

입력 칸을 직접 찾는 대신, 종이 여백에 인쇄된 검은 사각형 네 개를 찾습니다.

- **마커 찾기:** 각 모서리 사분면(`0:cy, 0:cx` 등)에서 면적이 $50 < \text{Area} < 5000$ 이고 가로세로 비율이 $0.7$에서 $1.3$ 사이인 윤곽선을 찾습니다.
- **원근 보정:** 네 점을 $2828 \times 2000$ 픽셀의 고정 캔버스에 맞춥니다.

```python
src = np.array([tl, tr, br, bl], dtype="float32")
dst = np.array([[0, 0], [temp_w, 0], [temp_w, temp_h], [0, temp_h]], dtype="float32")
warped = cv2.warpPerspective(img, cv2.getPerspectiveTransform(src, dst), (temp_w, temp_h))
```

### 2. 고정 비율로 자르기

모든 페이지가 같은 캔버스 위에 놓이면, 영역은 고정된 비율로 잘라 내면 됩니다. 윤곽선 검출이 필요 없습니다.

```python
ROIS_P1 = {
    'Student_ID':    {'x': (0.202, 0.518),   'y': (0.0534, 0.2051)},
    'DOB':           {'x': (0.5265, 0.719),  'y': (0.0537, 0.2044)},
    'Name':          {'x': (0.7285, 0.993),  'y': (0.0127, 0.0566)},
    'Wongoji_P1':    {'x': (0.0095, 0.993),  'y': (0.2207, 0.976)}
}
```

### 3. 투영으로 마킹 읽기

학번과 생년월일 칸을 읽을 때 `read_omr_smart`는 행과 열마다 어두운 픽셀 수를 더합니다. 이 합계의 봉우리와 골짜기가 칸의 경계를 알려 주는데, 인쇄된 OMR 답안지의 타이밍 마크와 비슷한 역할을 합니다.

- **마킹 여부:** 빨간 채널($I_R$)을 임계 처리해 빨간 격자선과 연필 자국을 분리한 뒤, 칸마다 채워진 비율을 계산합니다.

$$
\text{Ratio} = \frac{\text{NonZero}(I_R \le 180)}{\text{Cell Area}}
$$

비율이 $12\%$ 이상이면 마킹으로 보고, $5\%$에서 $12\%$ 사이는 애매한 경우(`!`)로 표시해 사람이 확인하도록 넘깁니다.

## 한글 결과 정리하기

원고지의 격자선 때문에 비전-언어 모델이 가끔 실제로는 없는 한글 음절을 만들어 냅니다.

유니코드 한글 음절 영역(`U+AC00`–`U+D7A3`)에는 초성, 중성, (선택적) 종성을 조합한 11,172자가 있습니다. 그중 실제로 자주 쓰이고 **KS X 1001** 표준에 들어 있는 것은 **2,350자**뿐입니다. 필터는 이 점을 이용합니다.

1. 인식 결과를 한 글자씩 확인합니다.
2. 한글 음절 영역에 속하는 글자인지 봅니다.
3. 속한다면 KS X 1001의 2,350자 중 하나인지 확인합니다.
4. 실제 한국어에 없는 음절은 지우거나 발음이 가장 비슷한 음절로 바꿔, 데이터베이스에 이상한 글자가 쌓이지 않게 합니다.
5. Kiwi(`kiwipiepy`) 형태소 분석으로 명사(`NNG`, `NNP`)를 뽑아 색인에 씁니다.
